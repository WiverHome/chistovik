## 1. Концепция и принципы

**Концепция — «верстальный стол».** Слева то, *что* вы настраиваете (разделы), в центре — *как* (форма), справа — *что получится* (живой лист A4 и кнопка «Создать шаблон»). Пользователь никогда не правит «вслепую»: любое изменение сразу видно на листе справа.

Принципы:

1. **Один главный путь — три действия.** Выбрать вид работы → заполнить титульный лист → «Создать шаблон». Правила и структура уже настроены по ГОСТ 7.32-2017; их открывают только те, чья методичка требует иначе. Кнопка «Создать шаблон…» доступна с любого раздела.
2. **Ничего не обязательно.** Пустые поля не ошибка: они попадут в шаблон подсказками в `[скобках]`. Интерфейс показывает, сколько подсказок останется, но не блокирует создание.
3. **Видно, что изменилось.** Отличия от ГОСТ отмечены в каждом правиле, сброс одним действием, отмена удаления и сброса — через инфобар «Отменить».
4. **Объясняем правило там, где его меняют.** У каждого правила есть описание простыми словами и значение по ГОСТ.
5. **Родной Windows 11.** Fluent-геометрия, Segoe UI, акцент #005FB8, стандартные контролы WPF с переопределёнными шаблонами. Никаких сторонних библиотек.
6. **Ничего не теряется.** Всё введённое сохраняется автоматически; явное «Сохранить» нужно только для экспорта профиля в файл.

## 2. Информационная архитектура и навигация

### 2.1. Карта приложения

```
Окно
├── Навигация (слева)
│   ├── 1. Вид работы            Ctrl+1   подстрока: название профиля
│   ├── 2. Титульный лист        Ctrl+2   подстрока: «Заполнено 4 из 11»
│   ├── 3. Правила оформления    Ctrl+3   подстрока: «ГОСТ 7.32-2017» / «Изменено: 2» / «Ошибок: 1»
│   ├── 4. Структура работы      Ctrl+4   подстрока: «2 главы · 4 параграфа»
│   └── (внизу) Параметры        Ctrl+,
├── Редактор (центр) — содержимое выбранного раздела
└── Предпросмотр (справа)
    ├── Режим: Титул | Страница | Содержание
    ├── Лист A4 в масштабе
    └── Панель создания: [ ] PDF, [ ] Открыть после создания, «Создать шаблон…»
Поверх окна: диалоги (создание шаблона, сохранение и отправка профиля, подтверждения)
```

### 2.2. Почему так

| Решение | Почему |
|---|---|
| Боковая навигация (как NavigationView в «Параметрах» Windows 11), а не вкладки и не мастер | Разделы неравноценны: большинство заходит только в «Титульный лист». Мастер заставил бы проходить ненужные шаги; вкладки не дают места для сводки состояния. Пункты навигации нумерованы и двухстрочные: вторая строка — сводка раздела, поэтому навигация одновременно служит чек-листом. |
| Предпросмотр — постоянная правая колонка, а не отдельная вкладка | Требование «видеть результат правок»: при вводе в любом разделе лист меняется рядом. Режим предпросмотра автоматически следует за разделом (титульный лист → «Титул», правила → «Страница», структура → «Содержание»), но его можно переключить вручную. |
| Кнопка «Создать шаблон…» живёт под предпросмотром, а не в шапке или в конце мастера | Это действие над тем, что видно на листе. Позиция постоянна во всех разделах, клавиша Ctrl+Enter работает отовсюду. |
| Вид работы — отдельный раздел с карточками, а не выпадающий список в шапке | Профилей больше двух (встроенные, импортированные, «скоро»), у каждого есть описание, у импортированных — меню действий. Карточки дают место под пустое состояние и импорт. Текущий профиль всё равно виден в навигации. |
| Правила — карточки «название + описание + контрол» как в «Параметрах» Windows 11 | Решает требование «подсказки, что значит каждое правило» без всплывающих окон: описание всегда на экране. |
| Создание — модальный диалог | Сборка идёт 5–30 с по снимку данных; правки во время сборки в файл не попадут и запутают. Диалог показывает этапы, итог и действия с файлом в одном месте. |
| Автосохранение вместо «Сохранить» | Студент закрывает приложение и возвращается через неделю — всё на месте. |

### 2.3. Поведение навигации

- Выбранный раздел и режим предпросмотра запоминаются. **Первый запуск** открывает «Вид работы» с приветственным инфобаром; последующие — «Титульный лист» (или последний открытый раздел).
- В конце разделов 1–3 есть кнопка «Далее: …» для тех, кто идёт по порядку. Её нет в разделе 4 — дальше только «Создать шаблон…».
- Смена раздела не теряет фокус-историю: при возврате в раздел прокрутка восстанавливается.
- Значки на пунктах навигации: красный кружок с числом — ошибки в разделе; акцентная точка — изменены правила относительно ГОСТ.

### 2.4. Данные и сохранение

| Что | Где | Когда |
|---|---|---|
| Поля титульного листа, общие для всех профилей (вуз, ФИО, группа…) | `%APPDATA%\KonstruktorShablonov\settings.json` → `fields` | автоматически, через 500 мс после последнего ввода и при закрытии |
| Поля, зависящие от профиля (`work_type`, `work_kind`, `ministry`, `org_form`) | `settings.json` → `profiles[id].fields` | так же |
| Изменённые правила и структура | `settings.json` → `profiles[id].overrides`, `profiles[id].structure` | так же |
| Импортированные профили | копия файла в `%APPDATA%\KonstruktorShablonov\profiles\` | при импорте |
| Выбранный профиль, раздел, режим предпросмотра, опции PDF/открыть, последняя папка, последний файл, тема | `settings.json` → `ui` | при изменении |

Поле `year`, оставленное пустым, всегда означает «текущий год» и не запоминается как число.

## 3. Каркас окна и раскладка

### 3.1. Окно

- Стандартная системная рамка и заголовок Windows 11 (snap-раскладки, скругление и тень окна — от ОС). Цвет заголовка совпадает с фоном окна через `DwmSetWindowAttribute(DWMWA_CAPTION_COLOR = 35)` = `Bg.Window`; в тёмной теме дополнительно `DWMWA_USE_IMMERSIVE_DARK_MODE = 20`. Mica не используется (непредсказуема в WPF), фон — сплошной цвет.
- Заголовок окна: `Конструктор шаблонов работ`. Значок — `icon.ico` из прототипа.
- `Width=1280 Height=800` (внешний размер), `MinWidth=1024 MinHeight=680`. Клиентская область при 100 % ≈ 1280×768 (системный заголовок 32 px) — все размеры ниже даны для неё.
- Окно открывается по центру основного монитора; размер, положение и `WindowState` запоминаются.

### 3.2. Сетка колонок (клиентская область 1280×768)

```
x: 0        240                                 880                      1280
   ┌────────┬───────────────────────────────────┬────────────────────────┐ y=0
   │ Навига-│ Редактор (слой, скругление 8      │ Предпросмотр 400        │
   │ ция    │ сверху слева/справа)              │ ├ шапка 48              │
   │ 240    │ ├ шапка раздела (отступ 32)       │ ├ холст с листом *      │
   │        │ └ прокручиваемое содержимое       │ └ панель создания 172   │
   │        │   ширина 640, контент 576         │                         │
   └────────┴───────────────────────────────────┴────────────────────────┘ y=768
```

| Колонка | Ширина | Фон | Примечание |
|---|---|---|---|
| Навигация | 240 (компактная 48) | `Bg.Window` | без рамки |
| Редактор | `*`, минимум 440 | `Bg.Layer` | `Border`: рамка `Stroke.Card` 1 px слева и справа, `CornerRadius="8,8,0,0"`, отступ сверху 0 |
| Предпросмотр | 400 (360 / 480 — см. 3.3) | `Bg.Window` | |

Содержимое редактора: отступы 32 слева/справа, максимальная ширина контента 760 (на широких окнах контент прижат влево, справа пустота).

### 3.3. Адаптивность

| Ширина окна | Навигация | Предпросмотр | Форма титульного листа |
|---|---|---|---|
| ≥ 1440 | 240 | 480 | 2 колонки |
| 1180–1439 (по умолчанию 1280) | 240 | 400 | 2 колонки |
| 1024–1179 | компактная 48 (только иконки, подписи — во всплывающих подсказках, кнопка ☰ разворачивает панель 240 поверх контента с тенью `Shadow.Flyout`; закрывается по Esc, клику вне, выбору пункта) | 360 | 2 колонки |
| Ширина контента редактора < 520 (например, при масштабе 150 %) | — | — | 1 колонка; строки правил переходят в вертикальную раскладку (контрол под описанием) |

**При минимальном размере 1024×680** (клиент ≈ 1024×648): навигация 48, предпросмотр 360, редактор 616 (контент 552, поля по 268 px). Лист A4 вписывается в высоту холста (≈ 272×384 px). Шапка и панель создания не сжимаются — сжимается только холст; редактор прокручивается. Если высота клиентской области < 600 (только при масштабировании ОС), строка «Последний шаблон…» в панели создания скрывается.

### 3.4. Навигационная панель

- Отступ сверху 8, снизу 8. Пункты по ширине панели с полями 4 слева/справа (ширина 232).
- **Основной пункт** (двухстрочный): высота 56, `CornerRadius 4`, между пунктами 4. Внутри: акцентная полоска выбора 3×16 у левого края (x=0, по центру по вертикали, радиус 1.5); иконка 16 px на x=12 (16 от края панели); текстовый блок с x=44: строка 1 — `Type.Body` `Text.Primary`, строка 2 — `Type.Caption` `Text.Secondary` (для ошибок — `Text.Error`). Справа (отступ 12) — значок: точка 6×6 `Accent.Default` («изменено») или кружок 16×16 `Fill.Error` с числом белым `Type.Caption`.
- Внизу: разделитель 1 px `Stroke.Divider` с полями 12, затем пункт «Параметры» высотой 36 (однострочный).
- **Компактная панель (48):** пункты 40×40 по центру (поля 4), только иконка; вторая строка и подпись — в `ToolTip` («Титульный лист — заполнено 4 из 11»). Значок «ошибки» — кружок 8×8 в правом верхнем углу иконки. Сверху — кнопка ☰ 40×40 `Subtle` (E700), `AutomationProperties.Name="Развернуть навигацию"`.
- Навигация — `ListBox` с `SelectionMode=Single`; стрелки ↑/↓ перемещают выбор, Enter/Пробел не требуются (выбор = переход).

### 3.5. Шапка раздела в редакторе

```
отступ сверху 24
Заголовок раздела   [статус-чип справа, по центру строки 36]   Type.Title 28/36 SemiBold
отступ 4
Подзаголовок (1–2 строки)    Type.Body Text.Secondary, макс. ширина 640
отступ 16 (если есть командная строка)
[Кнопка] [Кнопка] [Кнопка]   высота 32, промежуток 8
отступ 24
Содержимое…
```

Шапка прокручивается вместе с содержимым (не закреплена). Инфобары раздела (успех, отмена и т. п.) появляются между шапкой и содержимым, отступ снизу 16.

Группы содержимого: заголовок группы `Type.BodyStrong`, под ним 8, затем карточка; между группами 24. Внизу содержимого — 32 отступа; кнопка «Далее» выравнивается вправо, перед ней 24.

### 3.6. Колонка предпросмотра

| Элемент | Размеры |
|---|---|
| Шапка | высота 48, поля 24 слева/справа. Слева — сегментированный выбор режима (3 сегмента, высота 32), справа — кнопка-иконка «Увеличить» 32×32 (E740) |
| Холст | всё оставшееся место; поля 24 слева/справа, 8 сверху, 8 снизу. Лист A4 вписывается `Viewbox Stretch=Uniform` по центру по горизонтали, прижат к верху |
| Легенда | под листом, отступ 8, высота 20: квадрат 12×12 `Fill.Placeholder` + текст `Type.Caption` `Text.Secondary` (зависит от режима, см. 13.8) |
| Панель создания | высота 172, рамка сверху 1 px `Stroke.Divider`, поля 16 сверху/снизу, 24 слева/справа (см. 3.7) |

При 1280×800 лист — 352×498 px (масштаб 0,4435).

### 3.7. Панель создания

```
y+16  [✓] Сохранить также PDF                 чекбокс, строка 32
y+48  [✓] Открыть после создания              чекбокс, строка 32
y+92  ┌──────────── Создать шаблон… ─────────┐  Primary Large, 40 × на всю ширину
```

- Нижняя строка: до первого создания — «Ctrl+Enter — создать из любого раздела»; после — «Последний: {имя файла}» (обрезка середины, полный путь в подсказке) и гиперссылки «Открыть» и «Показать». Если файл с тех пор удалён — строка скрывается.
- Если Microsoft Word не найден: чекбокс PDF отключён (`IsEnabled=False`, снят, `ToolTipService.ShowOnDisabled=True`, подсказка «Для PDF нужен Microsoft Word»), а нижняя строка панели вместо подсказки Ctrl+Enter показывает «Word не найден — содержание обновится при открытии» с иконкой E7BA 12 px `Text.Warning`. Раскладка панели не меняется.

## 4. Экраны и состояния

### 4.1. «Вид работы»

**Шапка:** заголовок, подзаголовок, командная строка: [Импортировать профиль…] (Secondary, иконка E8B5).

**Первый запуск:** над группами — инфобар Informational (закрываемый, больше не появляется): заголовок «Добро пожаловать!», текст из 13.3.

**Блок «Определить по примеру»** — между инфобарами и группой «Встроенные профили», см. 17.2.

**Группа «Встроенные профили»** — сетка 2 колонки, промежуток 16 (колонка (576−16)/2 = 280), строки по 16.

| Карточка | Иконка | Состояние |
|---|---|---|
| Курсовая работа | E7BE (Education) | выбираемая |
| Выпускная квалификационная работа | EB95 (Certificate) | выбираемая |
| Реферат | E8A5 (Document) | отключена, значок «Скоро» |
| Отчёт по практике | E821 (Work) | отключена, значок «Скоро» |

**Карточка профиля** (`ProfileCard`, по сути `RadioButton` с шаблоном): высота 112, поля 16, `CornerRadius 8`. Слева плитка 40×40 `CornerRadius 6` `Fill.AccentSubtle`, иконка 20 `Accent.Text`. Справа от плитки (отступ 12): название `Type.BodyStrong`, ниже 4 — описание `Type.Caption` `Text.Secondary`, максимум 3 строки, обрезка многоточием. В правом верхнем углу: у выбранной — кружок 20×20 `Accent.Default` с галочкой E73E 12 px белой; у отключённой — значок «Скоро»; у импортированной — кнопка «…» 32×32 Subtle (E712) с меню.

**Группа «Профили кафедр»** — описание группы `Type.Caption` `Text.Secondary` под заголовком, затем та же сетка: импортированные профили + последняя карточка-кнопка «Импортировать профиль…» (рамка 1 px пунктир `Stroke.ControlStrong`, иконка E710 в плитке `Fill.Subtle`).

- **Пустое состояние:** в сетке только карточка импорта.
- Описание импортированной карточки: «Файл: {имя.json} · импортирован {дд.мм.гггг}».
- Меню «…»: «Показать файл» (E838), «Удалить из списка» (E74D) → диалог 7.5.
- Выбор карточки сразу переключает профиль: форма титула пересобирается, предпросмотр обновляется. Перетаскивание `.json` на окно в любом разделе = импорт.

**Внизу:** [Далее: титульный лист] (Secondary, иконка справа E72A).

### 4.2. «Титульный лист»

**Шапка:** заголовок; подзаголовок «Пустые поля останутся…»; статус-чип справа от заголовка (иконка E73E 12 + «Сохраняется автоматически», `Type.Caption`, `Text.Secondary`); командная строка: [Очистить поля] (Subtle, E894) → диалог 7.4.

**Группы и поля.** Набор полей строится из профиля: показываются только поля, которые встречаются в `title_page.blocks[*].lines`, `rows` и `bottom_lines` (поиск `{ключ}`). Метаданные полей — таблица ниже; ключ, которого в таблице нет (импортированный профиль), попадает в группу «Другое» с подписью = значение `fields_meta[ключ].label` из профиля, если оно есть, иначе сам ключ. (Предлагаемое расширение формата профиля: необязательный объект `fields_meta: { "ключ": { "label": "...", "group": "institution|work|student|supervision", "placeholder": "...", "help": "..." } }`.)

| Ключ | Подпись | Группа | Ширина | Тип | Профили |
|---|---|---|---|---|---|
| `university` | Университет | Учебное заведение | вся | TextBox | К, В |
| `institute` | Институт или факультет | Учебное заведение | вся | TextBox | К, В |
| `department` | Кафедра | Учебное заведение | ½ | TextBox | К, В |

**Подстановка значений из профиля:**
- Значение профиля в `[скобках]` или «И. О. Фамилия» = подсказка → поле пустое, текст подсказки (без скобок) становится частью плейсхолдера (см. 13.4).
- Любое другое значение профиля (например, «КУРСОВАЯ РАБОТА», министерство) = значение по умолчанию → подставлено в поле как текст.
- Счётчик «Заполнено N из M» считает только поля, значение которых по умолчанию — подсказка (курсовая: M = 11, ВКР: M = 14).

**Интерактивность с предпросмотром:**
- Фокус в поле → соответствующая строка на листе обводится рамкой 1 px `Accent.Default` (в масштабе листа) — видно, где окажется текст.
- Клик по строке/подсказке на листе → фокус в соответствующее поле (раздел «Титульный лист» открывается, если был другой). Курсор «рука», подсказка «Нажмите, чтобы заполнить: {подпись}».
- Обновление листа — при каждом изменении текста (без задержки; рендер дешёвый).

**Умные подсказки (не ошибки):** если в поле ФИО (`student`, `supervisor`, `head`, `normcontrol`) введено три слова без точек (например, «Иванов Иван Иванович»), под полем появляется `Type.Caption` `Text.Secondary` с иконкой EA80 (Lightbulb): «На титульном листе обычно пишут «И. И. Иванов».» и ссылка «Исправить» — заменяет значение. Если в `topic`, `university`, `discipline` введены внешние кавычки «» или "" — подсказка «Кавычки уже есть в шаблоне.» и ссылка «Убрать кавычки».

## 5. Предпросмотр

### 5.1. Общее

- Лист A4 рисуется в «бумажных» координатах: `Grid` 793,7 × 1122,5 DIP (210×297 мм при 96 DPI) внутри `Viewbox Stretch=Uniform`. Пересчёт: **мм → DIP ×3,7795; пт → DIP ×1,3333; см → DIP ×37,795**. Шрифты задаются реальными значениями — масштабирование делает `Viewbox`.
- Лист: фон `#FFFFFF` (всегда, и в тёмной теме), рамка 1 px `#E0E0E0`, тень `Shadow.Paper`, без скругления.
- Подписи размеров и подсветки рисуются **поверх** `Viewbox` в экранных координатах (иначе текст 11 px станет нечитаемым), позиция = бумажная координата × масштаб.
- Межстрочный интервал текста: `LineHeight = кегль(DIP) × 1,15 × интервал`, `LineStackingStrategy=BlockLineHeight`. Переносы в предпросмотре не показываются (WPF не умеет русские переносы) — это сказано в легенде режима «Страница».
- Неустановленный шрифт заменяется на Times New Roman.
- Режим выбирается автоматически при смене раздела (Вид работы/Титульный лист → «Титул», Правила → «Страница», Структура → «Содержание»); ручное переключение действует до следующей смены раздела.
- Кнопка «Увеличить» (E740) открывает диалог-просмотр: 90 % высоты окна, тот же лист в масштабе по высоте, сверху тот же переключатель режимов, Esc/«Закрыть».
- `AutomationProperties.Name` листа: «Предпросмотр: {режим}»; для чтения с экрана лист не дублирует текст (данные уже в форме).

### 5.2. Режим «Титул»

- Рендер блоков `title_page.blocks` выбранного профиля: выравнивание, `space_before_pt`, `indent_left_cm`, `bold`, `size_pt`; блок `signatures` — таблица без рамок с шириной колонок `col_widths_cm`; `bottom_lines` — у нижнего края, 10 мм от края листа (как колонтитул первой страницы).
- Кегль титула — `title_page.font_size_pt`, интервал 1,0, шрифт — из правил.
- Незаполненное поле выводится текстом подсказки в квадратных скобках на фоне `Fill.Placeholder` (#FFF4CE) цветом `#7A5800`; заполненное — обычным чёрным. Фокусированное поле — обводка 1 px `Accent.Default` вокруг строки.
- Год: пусто → текущий год обычным текстом (это не подсказка).

### 5.3. Режим «Страница» (схема)

- Зоны полей залиты `Fill.MarginZone` (#EAF2FB; тёмная тема — та же, лист светлый), граница текстового поля — пунктир 1 px (в экранных px) `#5B9BD5`.
- На полях — подписи размеров (поверх, `Type.Caption` 11/14 SemiBold, цвет `#1F5E99`): «30 мм» по центру левого поля и т. д.
- Внутри текстового поля образец: заголовок главы «1 Название главы» (по правилам: выравнивание, полужирный, кегль), абзац образца текста (2 абзаца, выравнивание, абзацный отступ, интервал, шрифт), подпись «Рисунок 1 – Схема процесса» (по правилам рисунка), подпись таблицы и мини-таблица 3×2 с кеглем «Шрифт в таблицах».
- Номер страницы «2» в нижнем поле, 10 мм от края, по центру/справа.
- **Подсветка правила в фокусе:** поля страницы — соответствующая зона заливается `#CFE2F6`, подпись размера полужирная; абзацный отступ — прямоугольник ширины отступа в первой строке абзаца, `Accent.Default` 30 %, подпись «1,25 см»; интервал — две горизонтальные линии между строками с подписью «1,5»; выравнивание — вертикальные пунктиры по краям текста; номер страницы — кольцо вокруг номера; заголовки/подписи — обводка соответствующего образца.

### 5.4. Режим «Содержание»

- Лист с заголовком «СОДЕРЖАНИЕ» по правилам структурного заголовка (прописные — если включено).
- Строки: Введение, главы (`1 Название`), параграфы (`1.1 Название`, отступ 0,5 см на уровень), Заключение, Список использованных источников, Приложение А… — только включённые и только уровни ≤ «Уровни в содержании». Отточия и условные номера страниц справа (3, 5, 7…); пустые названия — подсказки в скобках с `Fill.Placeholder`.
- Строка, соответствующая элементу в фокусе в списке структуры, обводится `Accent.Default`.
- Легенда: «Номера страниц условные».

## 6. Создание шаблона: поток и состояния

### 6.1. Поток

1. Нажатие «Создать шаблон…» или Ctrl+Enter.
2. **Проверка ошибок валидации.** Если есть — диалог не открывается: переход в раздел первой ошибки, фокус в поле, инфобар Error «Исправьте ошибки перед созданием шаблона» + текст «В разделе «Правила оформления» ошибок: 1.» Нав-значок уже показывает число.

Отмена диалога — ничего не происходит.

## 8. Валидация

**Правила показа:**
- Проверка — при каждом изменении (`UpdateSourceTrigger=PropertyChanged`) с задержкой показа ошибки 400 мс после последнего ввода и сразу при потере фокуса.
- Ошибочное значение остаётся в поле (без автокоррекции и без «отката»), предпросмотр использует последнее корректное значение.
- Состояние «ошибка»: нижняя линия поля 2 px `Text.Error`, рамка 1 px `Text.Error`; под полем строка `Type.Caption` `Text.Error` с иконкой E783 12 px; `AutomationProperties.HelpText` = текст ошибки; поле `Validation.HasError`.
- Ошибки считаются в навигации (значок) и блокируют только создание шаблона и сохранение профиля (переход к первой ошибке).
- Предупреждения (`Text.Warning`, иконка E7BA) не блокируют ничего.

| Поле | Условие | Тип | Текст |
|---|---|---|---|
| Поля страницы (×4) | не число или вне 0–50 | ошибка | «Введите число от 0 до 50» |
| Поля страницы | левое + правое > 80 | предупреждение (под сеткой) | «Широкие поля: для текста остаётся {N} мм» |
| Размер шрифта | не целое или вне 10–16 | ошибка | «Введите целое число от 10 до 16» |
| Абзацный отступ | не число или вне 0–2,5 | ошибка | «Введите число от 0 до 2,5» |
| Шрифт в таблицах | не целое или вне 10–14 | ошибка | «Введите целое число от 10 до 14» |
| Шрифт в таблицах | больше размера основного шрифта | предупреждение | «Обычно текст в таблицах не крупнее основного» |
| Шрифт | пусто | ошибка | «Укажите шрифт» |
| Шрифт | не установлен в системе | предупреждение | «Шрифт «{имя}» не установлен на этом компьютере — Word заменит его другим» |
| Количество приложений | не целое или вне 1–10 | ошибка | «Введите число от 1 до 10» |
| Год | не 4 цифры или вне 1990–2100 | ошибка | «Год — четыре цифры, например 2026» |
| Курс | не 1–6 | ошибка | «Курс — число от 1 до 6» |
| Любое поле титула / название главы | > 300 символов | ошибка | «Слишком длинный текст — не больше 300 символов» |
| Название профиля (диалог) | пусто | ошибка | «Введите название профиля» |

Числа принимаются с запятой и с точкой, отображаются с запятой (культура ru-RU). Ввод букв в числовые поля не блокируется (иначе непонятно, почему не печатается), а приводит к ошибке.

## 10. Доступность

- **Контраст** (WCAG 2.1 AA, проверено расчётом): основной текст #1B1B1B на #FFFFFF — 17,2:1; вторичный #5C5C5C на #F3F3F3 — 6,0:1; плейсхолдер #6B6B6B на #FFFFFF — 5,3:1; акцентный текст #005FB8 на #F3F3F3 — 5,7:1; белый на акценте #005FB8 / hover #1A6FC0 / pressed #004C93 — 6,3 / 5,2 / 8,6:1; успех #0F7B0F на #DFF6DD — 4,8:1; предупреждение #9D5D00 на #FFF4CE — 4,8:1; ошибка #C42B1C на #FFFFFF — 5,7:1. Границы интерактивных контролов (нижняя линия полей, рамка чекбокса и переключателя #868686) — 3,6:1 (требование 3:1 для нефтекстовых элементов). Тёмная тема — см. 11.1.
  - **Отличие от Windows 11:** «pressed» у акцентной кнопки сделан темнее (#004C93), а не светлее, чтобы сохранить контраст белого текста.
- **Фокус:** у всех интерактивных элементов видимая двойная рамка (12.1): внешняя 2 px `Focus.Outer`, внутренняя 1 px `Focus.Inner`, отступ 1 px от элемента, радиус элемента + 2. Только при навигации с клавиатуры (`FocusVisualStyle`), не при клике мышью. У текстовых полей фокус — нижняя акцентная линия 2 px + рамка (как в Windows 11), без двойной рамки.
- **Размеры целей:** стандартный контрол 32 px, кнопка создания 40, пункт навигации 56/40, строка списка 40. Единственное исключение — кнопки степпера 24×24 внутри числового поля (минимум WCAG 2.2 «24 px» соблюдён, плюс доступны ↑/↓ с клавиатуры).
- **Не только цветом:** ошибки — цвет + иконка + текст; изменённые правила — точка + текст «Изменено»; выбранная карточка — рамка + значок-галочка; подсказки на листе — фон + квадратные скобки.
- **Диктор (UIA):** у каждой кнопки-иконки `AutomationProperties.Name` (тексты в 13.13); `LabeledBy` у полей; `HelpText` = описание правила или текст ошибки; инфобары и итог создания — `LiveSetting`; карточки профиля — `RadioButton` с `Name` = название + «, выбрано»; список структуры — `AutomationProperties.Name` строки «Глава 1: {название}» / «Параграф 1.1: {название}».
- **Высокая контрастность:** при `SystemParameters.HighContrast = true` все кисти подменяются системными (`SystemColors.WindowBrushKey`, `WindowTextBrushKey`, `HighlightBrushKey`, `HighlightTextBrushKey`, `GrayTextBrushKey`, `HotTrackBrushKey`); тени и подсветка `Fill.Placeholder` отключаются, подсказки на листе остаются различимыми за счёт скобок и подчёркивания.
- **Анимации:** при `SystemParameters.ClientAreaAnimation = false` все переходы мгновенные; спиннер заменяется статичной иконкой E895 и текстом этапа.
- **Масштаб:** раскладка проверяется на 100/125/150/175 % — при 150 % на 1280×800 срабатывает переход формы в одну колонку (см. 3.3).
- **Тексты:** без «кликните сюда»; кнопки — глаголы; ошибки говорят, как исправить.

## 12. Компоненты и их состояния

Общие правила: hover и pressed меняют фон за `Motion.Fast`; disabled — `Opacity` не используется, цвета подменяются явно; фокус клавиатуры — двойная рамка (12.1).

### 12.1. Рамка фокуса (`FocusVisualStyle`)

`Border` вокруг элемента с отступом −3 px: внешний `BorderThickness 2` `Focus.Outer`, внутри ещё один `Border` `BorderThickness 1` `Focus.Inner`; `CornerRadius` = радиус элемента + 3 (для карточек 11, для кнопок 7).

### 12.2. Кнопка Primary (акцентная)

Высота 32 (Large — 40), поля по горизонтали 12 (Large — 16), мин. ширина 96, `CornerRadius 4`, текст `Type.Body` (Large — `Type.BodyStrong`), иконка 16 слева с промежутком 8.

|---|---|---|---|

| pressed | `Accent.Pressed` | нет | `Text.OnAccent` |

| disabled | `Accent.Disabled` | нет | `Text.OnAccentDisabled` |

## 15. Заметки по реализации в WPF

- **Структура:** MVVM; `MainWindow` = `Grid` 3 колонки (`ColumnDefinition` с `Width` из состояния ширины — `SizeChanged` окна переключает визуальное состояние `Wide/Normal/Compact` через `VisualStateManager` или биндинг к свойству VM). Разделы — `ContentControl` + `DataTemplate` по типу VM.
- **Контролы:** навигация — `ListBox`; карточки профилей — `ListBox` с `UniformGrid Columns=2` (+ `RadioButton`-семантика через `AutomationPeer`) или `ItemsControl` с `RadioButton`; сегменты — `ListBox` горизонтальный (`SelectionMode=Single`) — даёт стрелки бесплатно; переключатель — `CheckBox` с шаблоном; NumberBox — `UserControl` (`TextBox` + 2 `RepeatButton`); список структуры — `ListView` с плоской коллекцией элементов (глава/параграф с `Level`), отступ параграфов через `DataTrigger`; диалоги — `Popup` не использовать: оверлей в корневом `Grid` (`Panel.ZIndex`) с `FocusManager.IsFocusScope` и циклическим `KeyboardNavigation.TabNavigation=Cycle`.
- **Expander, ToolTip, ScrollViewer, ProgressBar, ContextMenu** — стандартные с переопределёнными шаблонами.
- **Предпросмотр:** `Viewbox` → `Grid 793.7×1122.5` → `Canvas`/`StackPanel` с `TextBlock`. Подсказки в строках титула — `Run` с `Background`. Связь «строка ↔ поле» — `Tag`/attached property с ключом поля. Обновление — через `INotifyPropertyChanged` тех же VM, что и форма.
- **Проверка Word:** наличие `HKEY_CLASSES_ROOT\Word.Application\CurVer` при запуске (без запуска Word). Генерация — существующий `make_template.py` или порт на C#; тайм-аут Word 120 с; отмена — `Process.Kill(entireProcessTree: true)` для PowerShell/Word.
- **Блокировка файла:** перед генерацией пробная попытка `File.Open(path, FileMode.OpenOrCreate, FileAccess.ReadWrite, FileShare.None)` — быстрый переход в состояние D до сборки.
- **Копирование файла в буфер:** `Clipboard.SetFileDropList`.
- **Перетаскивание .json на окно:** `AllowDrop=True` у корня; при `DragEnter` с файлом `.json` — полупрозрачный оверлей `Fill.AccentSubtle` 90 % с рамкой 2 px пунктир `Accent.Default` и текстом `type.dropHint` по центру. Документы (.docx, .doc, .rtf, .odt, .pdf) — см. 17.3.
- **DPI:** `PerMonitorV2` в манифесте.
- **Локализация:** все строки — в `Strings.resx` с ключами из раздела 13.

## 17. Определение правил по примеру

### 17.1. Задача и принципы

Студент часто не знает, какой ГОСТ у него в вузе, — у него есть пример работы или пара строк требований. Функция сама находит 16 правил раздела «Правила оформления» и отвечает на вопрос «какой это ГОСТ».

Принципы:

1. **Ничего не меняется без подтверждения.** Анализ только показывает найденное. Применяет пользователь, и сразу доступно «Отменить».
2. **Каждое значение объяснено.** У правила есть уверенность и обоснование: доля абзацев или цитата из текста. Вывод про ГОСТ — сравнение, а не вердикт нормоконтроля, и интерфейс так и говорит.
3. **Ненайденное не трогаем.** Правила, которых нет в источнике, остаются как были, и это написано явно.
4. **Всё локально.** Файл и текст никуда не отправляются, это видно в диалоге.
5. **Один диалог, два источника.** «Пример работы» и «Текст требований» дают одинаковый результат и одинаковый список правил.

### 17.2. Точки входа

| Где | Элемент | Поведение |
|---|---|---|
| «Вид работы» | Блок-приглашение над группой «Встроенные профили» (раскладка ниже) | Кнопки открывают диалог на нужной вкладке. Блок виден всегда; после первого применения сжимается до одной строки (см. ниже) |
| «Правила оформления» | Первая кнопка командной строки [Определить по примеру…] (Secondary, E721) | Открывает диалог на последней использованной вкладке (по умолчанию «Пример работы») |
| Окно целиком | Перетаскивание .docx / .doc / .rtf / .odt / .pdf | Открывает диалог на вкладке «Пример работы» и сразу начинает анализ (17.3) |
| Клавиатура | Ctrl+D; Ctrl+Shift+V | Ctrl+D открывает вкладку «Пример работы». Ctrl+Shift+V открывает «Текст требований» с текстом из буфера и сразу запускает определение, если в буфере ≥ 20 символов текста |
| Первый запуск | Текст приветствия (13.3, `type.welcome.text`) | Упоминает функцию; блок-приглашение находится сразу под приветствием |
| «Правила оформления» после применения | Строка «Источник правил» (17.8) | Ссылка «Показать результат» снова открывает последний результат |

**Почему блок на «Виде работы» стоит над профилями.** Неизвестный ГОСТ — главная неуверенность студента, и решается она до выбора правил. Вид работы (курсовая или ВКР) при этом остаётся выбором пользователя: найденные правила применяются к текущему профилю, что сказано в подвале диалога.

**Блок-приглашение** (`DetectPromo`): ширина контента (576 при 1280), поля 16, `CornerRadius 8`, фон `Fill.AccentSubtle`, рамка 1 px `Stroke.Card`, отступ снизу 24.

```
┌──────────────────────────────────────────────────────────────────────┐
│ [E721]  Есть пример работы или требования методички?                 │  плитка 40×40 Bg.Card, иконка 20 Accent.Text
│  40×40  Определим поля, шрифт и интервалы сами и подскажем,          │  заголовок Type.BodyStrong
│         на какой ГОСТ это похоже.                                    │  текст Type.Body Text.Secondary
│         [Загрузить пример…]  [Вставить требования…]                  │  Secondary 32, промежуток 8, отступ сверху 12
└──────────────────────────────────────────────────────────────────────┘
```

После первого успешного применения в текущем профиле блок сжимается до строки высотой 48: иконка 16 + «Правила определены по примеру «{источник}»» + ссылка «Определить заново». Это нужно, чтобы не занимать место у тех, кто уже воспользовался функцией.

### 17.3. Перетаскивание файла на окно

- `.json` → импорт профиля, как раньше (§4.1).
- `.docx`, `.doc`, `.rtf`, `.odt`, `.pdf` → оверлей с иконкой E721 32 и текстом `detect.drop`. После отпускания открывается диалог с этим файлом в состоянии «Анализ».
- Несколько файлов → берётся первый поддерживаемый, в результате строка `detect.multiDrop`.
- Неподдерживаемый тип → оверлей не появляется, курсор «запрещено».
- Если открыт любой другой диалог, перетаскивание игнорируется. Если открыт диалог определения, файл принимает его зона на вкладке «Пример работы»: подсветка — рамка 2 px пунктир `Accent.Default`, фон `Fill.AccentSubtle`.

### 17.5. Применение

1. «Применить N правил» записывает отмеченные значения в правила текущего профиля так же, как ручное редактирование: пересчитываются «Изменено · по ГОСТ», счётчик и предпросмотр. Неотмеченные и ненайденные правила не меняются. Ошибочные значения (§8) в тех правилах, которые применяются, заменяются найденными.
2. Диалог закрывается. Приложение переходит в «Правила оформления» и прокручивает раздел к началу, предпросмотр — в режим «Страница».
3. Инфобар Success: `detect.applied` (+ `detect.applied.verdict`, если вердикт «Совпадение») и кнопка «Отменить» (Ctrl+Z). Отмена возвращает все правила к значениям до применения одним шагом. Инфобар исчезает при следующем ручном изменении правил.
4. **Подсветка.** У применённых правил строка изменения получает текст `detect.row.applied` вместо «Изменено · по ГОСТ», с той же точкой и ссылкой «Вернуть». Пометка держится, пока пользователь не изменит это правило вручную или не нажмёт «Сбросить». У применённых правил с низкой уверенностью ниже — предупреждение `detect.row.checkLow` (`Text.Warning`, E7BA 12).
5. **Фокус** переходит на контрол первого применённого правила. Инфобар озвучивается через `LiveRegionChanged` (Polite).
6. **Источник правил.** Под подзаголовком раздела «Правила оформления» появляется строка (17.8). Источник сохраняется в профиле: `settings.json` → `profiles[id].detected = { source, kind, verdict, standard, appliedAt, result }`, где `result` — снимок результата для «Показать результат». Строка пропадает после «Сбросить к ГОСТ» или если вручную изменены все применённые правила.

Найденные правила не создают новый профиль. Чтобы раздать правила, используется «Сохранить профиль…» (§7.1). Название по умолчанию в этом случае — «{профиль} — по примеру «{источник без расширения}»».

### 17.7. Доступность

- Диалог: `AutomationProperties.Name` = «Определить правила по примеру». Сегменты — `Name` «Источник правил».
- Зона выбора — кнопка с `Name` «Выбрать файл примера» и `HelpText` = `detect.file.formats`.
- Строка списка (`ListViewItem`) получает `Name`: «{Правило}: {значение}. Уверенность {уровень}. {Обоснование}. Сейчас: {текущее}». Для совпадающих — «… Уже так». Чекбокс внутри не отдельная остановка, состояние берётся через `TogglePattern` строки.
- По завершении анализа — `LiveRegionChanged` (Assertive) с текстом `detect.announce`. Ошибки — Assertive.
- Уверенность передаётся словом, вердикт — заголовком и иконкой. Цвет нигде не единственный признак.
- Контрасты значков уверенности — в 17.4.5. Все цвета — токены §11. В тёмной теме те же токены (контрасты из §11.1).
- Высокая контрастность: значки уверенности получают рамку 1 px `SystemColors.WindowTextBrush` и системный фон. Пунктир зоны — `WindowTextBrush`.
- Анимации нет, кроме спиннера. При `ClientAreaAnimation = false` спиннер заменяется на E895.

### 17.11. Чек-лист приёмки

- [ ] Все три точки входа и Ctrl+D / Ctrl+Shift+V открывают диалог на нужной вкладке. Перетаскивание .docx сразу запускает анализ, .json по-прежнему импортирует профиль.
- [ ] Короткий анализ проходит без мигания «Анализ», долгий (через Word) можно отменить.
- [ ] Ошибки E1–E7 воспроизводимы, в каждой есть путь дальше: другой файл, текст или повтор.
- [ ] По умолчанию отмечены строки с высокой и средней уверенностью. Строки «уже так» не отмечаются и не считаются.
- [ ] Применение меняет только отмеченное. «Отменить» возвращает всё одним шагом. Строки помечены «Из примера», низкая уверенность — предупреждением.
- [ ] Диалог помещается при 1024×680 (тело прокручивается, подвал виден).
- [ ] Диктор объявляет итог анализа и читает строку правила целиком.
